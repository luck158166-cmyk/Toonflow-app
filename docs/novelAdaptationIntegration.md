# 小说改编能力接入记录

## 来源与取用范围

- [Drama Skills](https://github.com/zenstory-ai/drama-skills)（MIT）：参考其只读原文索引、章节行号、原文变更检测和跨阶段证据传递。当前 TypeScript 实现独立编写，没有运行其 Python 脚本，也没有引入其工作区结构。
- [shuohao-skills](https://github.com/eternityspring/shuohao-skills)（Apache-2.0）：参考其剧本与分镜分层、动作与对白节拍、单句长度、说话人和时长规则。当前 TypeScript 实现独立编写；未复制其脚本或模板。

## 当前接入

`packages/production/src/novelAdaptation.ts` 从已导入的小说原文生成章节索引。它保存 SHA-256、原文行号和章节字数，报告无标题、章号异常、短章及章前长文本。索引是只读派生结果；有疑点时必须先校对边界，不能让模型据此自动改编。

同一模块对已保存的结构化分场剧本做基础检查：场景地点、动作节拍、人物说话人、单句台词长度、章节行号证据和可选目标时长。报告经生产接口显示在工作台。基础检查通过不代表剧情质量或生产就绪，不能替代原著忠实度、人物弧、钩子和悬念的内容审查。

## 尚未完成的改编链

逐章事件提取、人物状态与关系归并、分集规划、自动写剧本、版本管理、出处覆盖率和模型质量评审尚未接入。以上工作应继续沿 `docs/masterPlan.md` 阶段 8 的数据模型及费用约束实现；真实模型调用仍为零授权。剧本基础报告目前是只读提示，尚未接入媒体任务提交的硬闸门。

## 2026-11-07 原文证据入库闸门

结构化小说分集草稿在写入前，逐项核验剧本场次、人物、场景、道具、镜头及镜头道具互动的原文证据。证据须携带当前原文 SHA-256、章节序号、正文行号范围和逐字可在范围内找到的摘录；任一项不符就拒绝整份草稿，事务不会留下部分资产或分集。梗概和现成剧本当前仍允许旧式文字证据，以免误把小说专用行号规则套用到其他输入。

隔离 QA 验证了有效引用、错摘录、过期哈希、章节标题行，以及错误草稿不入库。该检查只证明“引用确实出现在原文对应位置”，不能证明人物设定、道具描述或剧情改编与该引用在语义上相符。自动故事分析、模型调用和内容质量评分仍未实现，真实 API 调用与费用仍为 0。
