## 1. 项目目标与已确定的决策

### 1.1 目标

个人使用（后续可能商用）的 AI 短剧自动生产系统：输入小说、故事梗概或已有剧本，自动完成改编、分集、剧本、角色/场景/道具资产、分镜、视频生成、对白配音、字幕、配乐、剪辑合成与质量检查，输出 9:16、1080×1920 的完整 MP4。支持多集连续剧批量生产，Windows 10/11 本地运行。

**成功标准不是"能演示"，而是：在用户设定的单集预算内，以尽可能高的一次通过率稳定产出可发布的成片，失败只局部重做，绝不重复付费。**

### 1.2 已确定的决策

| 项目 | 决策 |
|---|---|
| 宿主项目 | **Toonflow-app**（https://github.com/HBAI-Ltd/Toonflow-app ，MIT）。在其源码上二次开发，保留其全部原有功能 |
| 第二项目 | **Jellyfish**（https://github.com/Forget-C/Jellyfish ，Apache-2.0）。**不运行其后端**，把它的生产管理数据结构、提取与合并流程、状态语义、就绪判定、提示词上下文构建等**设计与逻辑用 TypeScript 移植**进 Toonflow |
| 模型平台 | 全部使用**火山方舟**：视频 Seedance（主力 2.5）、图片 Seedream 5.0、配音 豆包语音合成、语音识别 豆包录音文件识别、语言模型 DeepSeek（编剧类任务）+ 豆包快速模型（结构化任务） |
| 画幅 | 默认 9:16，1080×1920，H.264 + AAC 的 MP4 |
| 运行方式 | Windows 本地原生运行，服务只监听 127.0.0.1 |
| 生产数据 | 新增本地 SQLite（Bun 内置 `bun:sqlite`）作为生产数据唯一真相源；画布是视图 |
| 开发方式 | 分阶段，每阶段 Git 提交并停下汇报；先做一集最小闭环，再自动化 |

## 2. 两个开源项目的源码事实

### 2.1 Toonflow-app（已核实）

**技术栈与结构**
- Bun + TypeScript monorepo。`apps/server`（Express 5）、`apps/web`（Vue 3）、`apps/desktop`（Electrobun 桌面端）、`apps/mobile`（安卓）、`packages/*`。
- 服务入口 `apps/server/src/index.ts`：端口默认 3000（环境变量 `TOONFLOW_SERVER_PORT`），`app.listen(realPort, ...)` **未指定监听地址**；业务接口**无登录鉴权**。
- 路由按文件自动生成：`apps/server/src/routes/**/*.ts` 一个文件一个接口，新增后在 `apps/server` 执行 `bun run routes` 生成 `router.ts`（禁止手改）。
- 数据目录：开发环境为仓库根 `data/`，生产为安装目录 `data/`；全局设置 `data/settings.json`（`conf` 库，权限 0o600）。
- 磁盘操作统一走 `@toonflow/file`（`packages/file`），完整快照写入用 `writeAtomic`。
- **单机模式没有数据库**。项目数据是工作区目录中的 JSON 画布文件。SQLite/MySQL 只出现在 `packages/multiTenant`（多租户，本项目不触碰）。
- 全仓库 **0 个测试文件**，且 `AGENTS.md` 明确**禁止新增测试文件和测试框架**（见第 17 节处理方式）。

**媒体供应商机制（`packages/providers`，本项目的关键复用点）**
- 类型定义 `packages/providers/types.d.ts`：`ProviderDefinition` 包含 `rules`（配置表单，含 apiKey）、`models`（能力声明：`mode`、`audio`、`durationResolutionMap`、`imageSizes`、`imageRatios`、`voices`、模型专属 `rules`）、`generateImage` / `generateVideo` / `generateAudio`、**`resumeTask`（任务恢复，不重复提交）**、**`getPrice`（只读估价）**、**`getBalance`（余额）**、`processMedia`（预处理）、`checkForUpdates`。
- `ProviderContext.saveTaskData`：供应商接单后立即持久化恢复数据（不含密钥）。
- `VideoRequest` 支持 `images` / `videos` / `audios` / `firstFrame` / `lastFrame` / `duration` / `ratio` / `resolution` / `generateAudio` / `watermark` 及供应商专属 `other`；视频模式包括首帧、首尾帧、文本、`imageReference:N` 等多参模式；提示词中用 `{{ref N}}` 引用素材，供应商按 `referenceOrder` 替换为平台写法（示例：`packages/providers/src/media/metaso.ts` 的 `videoPrompt`）。
- `AudioRequest` 支持 `text`、`voice`、`speed`、`volume`、`pitch`、`emotion`、`language`、参考音频等。
- 供应商工具 `ProviderTools`：`fetch`、`errorMessage`（脱敏）、图片尺寸检查与缩放、WAV 裁剪转码、**FFmpeg 工厂**。
- 现有媒体供应商：`apiMart.ts`、`compshare.ts`、`metaso.ts`（`packages/providers/src/media/`）；语言供应商 `deepSeek.ts`，另支持 OpenAI 兼容协议。**没有火山方舟供应商**，需要新增。
- 用户也可把供应商 `.ts` 文件装到 `data/providers/`。

**媒体任务持久化（`apps/server/src/utils/media/`）**
- `tasks.ts`：任务记录（`state`: running / interrupted / succeeded / failed / cancelled，`checkpoint.providerData`，结果文件带哈希，按工作区存储，原子写入）。
- `generation.ts`：调用供应商；中断后通过 `resumeTask` 恢复，**不重新提交**；二进制直接落盘到工作区。
- `billing.ts`、`priceReference.ts`：估价与余额刷新（展示用，**不是费用账本**）。
- 路由：`routes/ai/media/generate.ts`、`price.ts`、`balance.ts`、`tasks/status.ts`、`tasks/cancel.ts`。
- 结论：**单次媒体生成的提交、等待、恢复、落盘已有可靠实现，必须复用**；缺的是"这次生成属于哪个项目/剧集/片段、花了多少钱、是否超预算、是否重复点击"这一层。

**画布、节点、Agent、技能**
- 画布节点（`packages/nodes`）：`textNode`、`imageNode`、`imageGenerationNode`、`videoNode`、`videoGenerationNode`、`audioNode`、`audioGenerationNode`、`director3dNode`、`frameAnalysisNode`。
- Agent 运行时基于 `@earendil-works/pi-coding-agent`（`apps/server/src/agent/`）：子 Agent、Agent 团队、委派、A2A、全局记忆（`agent/tools/memory.ts`，**一份全局 Markdown 文档，不是向量检索**）。
- Agent 工具包（`packages/tools`）：askUser、assetOperator、browser、canvas、ffmpeg、sandbox、skillOperator、webFetch、webSearch、workspace 等；MCP 服务（`packages/mcp`）。
- 技能（`packages/skills`）：`v118workflow`（14 步分集制作流程，每步等用户确认）、`workflow`、`canvas`。其中知识文档有较高价值：`knowledge/scriptCraft.md`（编剧方法）、`narrativeGenres.md`（叙事类型）、`shotCraft.md`（镜头）、`assetDesign.md`（资产设计）、`visualStyles.md`（美术风格）、`imagePromptCraft.md`、`videoPromptCraft.md`（含 Seedance 2.0 三段式模板）。
- **事件提取只是提示词**（`v118workflow/references/sourceEvents.md`，产出写进画布的 7 列事件表），代码中不存在事件图谱。
- 其他包：`packages/ffmpeg`（fluent-ffmpeg 封装，支持 concat）、`packages/asr`（语音识别，**能力待核实**）、`packages/nodeShared`、`nodeScaffold`、`toolScaffold`。
- Windows 打包：`apps/desktop/scripts/packageWindows.ts`，Electrobun 构建；有 Windows 更新器。

### 2.2 Jellyfish（已核实）

- 后端 Python：FastAPI + SQLAlchemy（异步）+ Celery + Redis + MySQL + RustFS 对象存储；前端 React（`front/`）；Docker Compose 部署。
- **数据模型**（`backend/app/models/`）：
  - `studio_projects.py`：项目、章节。
  - `studio_shots.py`：`Shot`（章节内序号、状态、剧本摘录、跳过提取、最近提取时间、生成视频文件）、`ShotDetail`（景别、机位、运镜、场景、时长、画幅覆盖、情绪标签、氛围、视效、动作拍点 `action_beats`、首帧/尾帧/关键帧提示词、提示词模板）、`ShotFrameImage`、`ShotDialogLine`（对白/旁白/画外音/电话音，说话人与听者角色）、`ShotCharacterLink`、`ShotExtractedCandidate`（资产候选：pending/linked/ignored）、`ShotExtractedDialogueCandidate`（对白候选：pending/accepted/ignored）。
  - `studio_assets.py`、`studio_asset_images.py`：角色/演员、场景、道具、服装及其多视角图。
  - `task.py`、`task_links.py`：统一生成任务及其与实体的关联。
  - `studio_prompts_files_timeline.py`：提示词模板（类别、变量、默认、系统预置）、文件、时间线片段（**时间线接口 `api/v1/routes/studio/timeline.py` 只是空壳**）。
  - `types.py`：景别（ECU/CU/MCU/MS/MLS/LS/ELS）、机位、运镜、视效类型、对白模式、项目风格、资产视角等枚举。
- **剧本处理链路**（`backend/app/schemas/skills/script_processing.py`、`chains/agents/`）：
  1. `script_divider`：按**行号区间**把章节剧本拆成镜头（`ShotDivision`：序号、起止行、摘录、镜头名、时间）。
  2. `element_extractor`：逐镜提取角色（外貌、本镜服装、配饰、临时状态）、道具（外观、状态、互动）、场景（地点细节、氛围、时间天气）、对白、动作、镜头类型提示，**每项带原文证据 `evidence` 与原始片段**，附置信度。
  3. `entity_merger`：跨镜合并为稳定实体（稳定 ID、归一化名、别名、首次出场证据），并记录**变体**（如换装、受伤状态及涉及镜头）。
  4. `consistency_checker`、`script_optimizer`、`script_simplifier`、`variant_analyzer`，以及角色/场景/道具/服装专项分析 Agent。
- **状态语义约定**（Jellyfish `AGENTS.md`）：镜头"信息确认状态"、"运行时任务状态"、"视频生成准备度"三者严格分离，不混用一个字段。
- **就绪判定**：`services/studio/shot_preparation_state.py`、`shot_video_readiness.py`。
- **实体查重**：`services/studio/entity_existence.py` + `entity_merger_agent.py`。
- **提示词**：`chains/agents/shot_frame_prompt_agents.py`（首/尾/关键帧规则：首帧只写触发瞬间，不写结果态等）；`services/studio/shot_video_prompt_pack.py`（构建前后镜承接、构图锚点、朝向视线、动作拍点）。其最终视频提示词是"字段：值"罗列，并夹带"避免跳轴"等说明文字，**不适合直接发给视频模型**。
- 视频供应商仅 OpenAI 与火山（`core/integrations/`），视频输入契约只支持首帧/尾帧/关键帧三张图（`core/contracts/video_generation.py`），不覆盖 Seedance 2.5 的全模态参考。
- 生成单位是**单个镜头**，没有多镜头片段的概念；没有后期合成；没有费用账本。

## 3. 取长补短：总体设计

### 3.1 优劣对照

| 维度 | Toonflow | Jellyfish | 本系统取用 |
|---|---|---|---|
| 运行与分发 | Windows 桌面端、安装包、更新器、单进程 Bun | 需 MySQL/Redis/Celery/对象存储 | **Toonflow** |
| 交互界面 | 无限画布、节点、插件市场、21 种语言 | 表单式工作台 | **Toonflow 画布** + 新增生产控制台 |
| 模型接入 | 供应商插件体系（能力声明、估价、余额、任务恢复） | 两家供应商、契约窄 | **Toonflow 供应商体系**，新增火山供应商 |
| 媒体任务可靠性 | 持久化任务、断点恢复、不重复提交、结果落盘 | Celery 任务表 | **Toonflow 媒体任务**作为执行层 |
| 生产数据结构 | 无（画布 JSON） | 完整的项目/章节/镜头/资产/对白/任务模型 | **Jellyfish 模型**（移植并扩展） |
| 剧本→镜头→资产 | 由 Agent 读 Markdown 技能自由执行，结果不确定 | 结构化链路：拆镜→逐镜提取（带证据）→实体合并（别名、变体） | **Jellyfish 链路**，用 Toonflow 的编剧知识增强提示词 |
| 人工确认 | 每一步对话确认 | 候选确认（待处理/关联/忽略） | **Jellyfish 候选机制**，自动模式按规则自动确认 |
| 状态管理 | 节点内状态 | 三态分离 | **Jellyfish 三态分离** |
| 创作方法知识 | 编剧、叙事类型、镜头、资产、风格、提示词知识库 | 较少 | **Toonflow 知识库** |
| 视频提示词 | Seedance 2.0 三段式模板贴合官方 | 字段罗列式，不适合 | **Toonflow 模板**，按官方 2.5 指南改写 |
| 镜头连续性 | 提示词层面约束 | 前后镜承接、构图、视线上下文构建 | **Jellyfish 上下文构建**作为提示词输入 |
| 后期 | FFmpeg 封装 | 无（时间线空壳） | **Toonflow FFmpeg** + 新增合成引擎 |
| 成本 | 估价展示、余额 | 无 | **新增**费用账本与预算 |
| 调度 | 无 | Celery 异步执行 | **新增**生产调度器 |

### 3.3 核心设计原则

1. **生产库是唯一真相源。** 剧本、镜头、资产、任务、费用都在 SQLite；画布 JSON 是生产库的投影，用户在画布上的修改只有经"采用"操作才写回生产库（第 13 节）。
2. **编排是确定性代码，语言模型只做有类型的填空。** 流水线每一步是一个状态机节点；需要语言模型的地方调用"结构化步骤"：固定输入、固定提示词模板、zod 校验输出、失败按规则重试。不让一个自由 Agent 读长文档决定流程。原因：结果可复现、可计费、可断点续跑、出错能定位。Toonflow 的对话 Agent 保留，作为用户的创作助手，可通过工具读写生产库（第 11 节）。
3. **三态分离（来自 Jellyfish）。** 任何实体都区分：内容确认状态、运行时任务状态、生成就绪度。界面分别展示。
4. **候选确认（来自 Jellyfish）。** AI 提取的角色、场景、道具、对白、变体先作为候选；人工模式由用户确认，自动模式按置信度与规则自动确认并记录"自动确认"。已锁定的资产永远不会被候选覆盖。
5. **可追溯（来自 Jellyfish 的证据机制）。** 每个事件、角色特征、剧本段落都记录来源（小说章节与段落、或上游步骤 ID）。检查剧情矛盾和人设冲突时以证据为依据。
6. **片段是视频生成单位。** 剧集 → 场次 → 片段 → 镜头。一个片段 = 一次 Seedance 调用，包含同一场次内连续的若干镜头（第 6.7 节）。Jellyfish 的"镜头"在本系统中是片段内的描述单位。
7. **提示词由编译器生成。** 代码模板 + 语言模型填空 + 静态检查器，提交前必须通过（第 7 节）。
8. **先拦后花。** 每次付费调用前依次通过：就绪检查 → 提示词检查 → 幂等检查 → 预算预留。任何一关不过都不产生费用。
9. **失败局部化。** 失败只影响当前片段或当前步骤；合成失败不触发任何生成；已成功的产物永不重复付费生成。
10. **复用优先，宿主规范优先。** 能用 Toonflow 现有机制的绝不另写；代码风格、目录、命名遵守 Toonflow `AGENTS.md`。新增代码集中在新包和新目录，尽量少改原文件，方便以后合并上游更新。

## 4. 火山方舟平台事实与约束

> 来源（2026-11-06 查证）：文档索引 https://ark.volcengine.com/llms.txt （任一文档地址后加 `.md` 可取 Markdown 版）。阶段 0 必须重读以下文档，以最新版为准：《Doubao Seedance 2.0 系列提示词指南》《Doubao Seedance 2.0 系列教程》《Doubao Seedance 2.5 教程》《Doubao Seedance 2.5 提示词指南》《Doubao Seedance 便利创作含肖像视频》《视频生成教程》《Seedream 4.0-5.0 提示词指南》《Doubao Seedream 5.0 pro / flash 教程》《图片生成教程》《Seedream 4.0 助力 Seedance 生视频最佳实践》《Doubao-语音合成-2.0》模型页、《Doubao-录音文件识别》模型页、《Seedance 2.5 与 Seedance 2.0 系列模型开通、使用与退订说明》《Seedance 2.0-2.5 模型资源包使用规则》。

### 4.1 视频模型

| 模型 | Model ID | 时长 | 要点 |
|---|---|---|---|
| **Seedance 2.5（默认）** | `doubao-seedance-2-5-260628` | 4–30 秒，或 -1（模型自选） | 参考素材最多 50 个（图 ≤30 张、视频 ≤10 段且总长 ≤30 秒、音频 ≤10 段且总长 ≤30 秒）；**响应整数秒时间戳**；1–5 个主体时多视图可用；**样片（Draft）模式**；输出 mp4 / mov；1080p 为 10bit H.265 |
| Seedance 2.0 | `doubao-seedance-2-0-260128` | 4–15 秒 | 不响应时间戳，只认"镜头 N"；不建议多视图/三视图作参考；1080p 为 8bit |
| Seedance 2.0 fast / mini | `doubao-seedance-2-0-fast-260128` / `doubao-seedance-2-0-mini-260615` | 4–15 秒 | 更快 / 更便宜，无样片模式 |

- 分辨率 480p / 720p / 1080p；9:16 对应 480×854、720×1280、1080×1920。宽高比可选 16:9、4:3、1:1、3:4、9:16、21:9、adaptive。
- **2.0 与 2.5 美学风格差异明显**：同一项目锁定一个视频模型，正片不得混用。
- 任务类型由素材 `role` 与提示词意图决定：文生视频；首帧/首尾帧（`role=first_frame/last_frame`，`ratio` 必须 `adaptive`）；全模态参考（`reference_image/video/audio`），其中又分参考生视频、编辑（`ratio=adaptive`、`duration=-1`，参考视频 4–30 秒）、延长（`ratio=adaptive`）。2.5 可传 `omni_reference_task_type` 让参数错误同步报出。**适配器必须按任务类型预校验参数。**
- **样片模式（仅 2.5）**：请求加 `draft=true`，只能 480p，价格与 480p 正常生成一致；确认后用样片任务 ID 生成正式视频，复用模型、提示词、素材、种子、音频设置、宽高比、时长。样片任务 ID 有效期 14 天（2026-10-28 之后创建的任务）。具体调用字段以官方文档为准。
- 支持"返回尾帧"能力，可用于下一片段的衔接参考（参数名阶段 0 核实）。
- 任务结果中的视频 URL **仅 24 小时有效**，必须立即下载。
- 任务结果包含 token 用量（官方示例中有 `usage` 字段），用于结算费用（计费公式阶段 0 核实）。
- 开通 Seedance 2.5 需账户余额 ≥ 200 元或已购资源包。
- 输出仍可能因平台安全审核失败；错误码表阶段 0 核实，用于区分可重试与不可重试错误。

### 4.2 真人人脸素材限制（决定角色资产方案）

Seedance 2.0 / 2.5 **不接受直接上传含真人人脸的参考图或视频**。可用来源：
1. **信任的模型原始产物**：同一账号、生成后 **30 天内**的：Seedance 2.x 含人脸视频及其尾帧；**Seedream 5.0 lite / pro / flash 文生图**得到的含人脸图片。二次剪辑、压缩、转发会失去信任；仅限方舟平台、同账号。官方建议原始产物直接转存对象存储使用。
2. **预置虚拟人像库**：以 `asset://<asset ID>` 传入，长期可用；提示词中仍用"图片 N"指代。
3. **已授权真人素材**：通过平台的真人认证录入流程。

系统要求：
- 写实风格角色参考图必须由 Seedream 5.0 **文生图**直接生成，原始文件原样保存并记录哈希；界面展示用另存的缩略图。
- 每张参考图记录生成模型、生成时间、**信任到期日**。到期前 7 天预警（天数可配置）。
- 连续剧制作周期超过 30 天会导致参考图失效，应对方案由用户在阶段 0 选择（第 20 节）。
- 图生图产物、动漫/3D 风格是否触发人脸审核：**官方未明确，阶段 3.5 实测**。
- 本地文件以何种方式传给 Seedance 才算"原始产物"（URL、base64、对象存储）：**阶段 0 核实**，必要时需要用户开通火山对象存储（TOS）。

### 4.3 官方提示词要点（第 7 节据此制定规则）

Seedance 2.0：
- 主体定义：`将<图片N>中的[2–3 个稳定静态特征]定义为<主体名>`，后文始终用同一称呼。
- 用"镜头 1 / 镜头 2"按事件顺序组织；**不写精确秒数**；每镜按"运镜 → 主体动作与表情 → 位置空间 → 音频"组织。
- 每个镜头只用一种运镜；优先缓慢、连贯的小动作；情绪用肢体细节外化。
- 符号：音乐 `（）`、音效 `<>`、台词 `{}`、字幕 `【】`。
- 角色参考用**大头照 + 全身照**，不用三视图；素材总数 4–5 个为宜；同画面人物 ≤4。
- 竖屏比横屏更容易生成多余字幕；不要把完整剧本当提示词；多音字可用同音常用字替换。
- 已知不可完全避免：双胞胎（分身）、多余字幕；官方给出降低概率的约束句。

Seedance 2.5：
- 结构：**素材指代 → 一句话概述 → 具体情节（连续的整数秒时间戳或"镜头 N"）→ 结尾（贯穿全片的机位、环境、声音、氛围）**。
- 素材按**角色首次出场顺序**上传，编号同步，否则角色对应错位。
- 台词差异化要求用 `角色台词（情绪）："内容"` 格式；**在台词后复述原话并追加语气描述会诱发字幕**。
- 强烈情绪词（狂热、极度震惊）易导致眼睛发光；改用常规描述，必要时写"人物眼睛为正常人眼、不发光"。
- 禁止 BGM 时要穷举"音乐、背景音乐、BGM、配乐、器乐、旋律、合成器音效、氛围铺底音"等同义词，并在提示词**开头和结尾各写一次**。
- 参考图分辨率**不超过输出分辨率**（否则草地、树叶出现指纹状纹理）。
- 画面中需准确显示的文字做成图片作为参考；参考视频本身不得含字幕。
- 复杂任务拆成多个简单任务再后期合成。
- 编辑任务输出可能短约 0.3 秒；输入帧数为 8n+1 时可保持一致。
- 特殊色度采样的 JPG 会解码失败，上传前用 FFmpeg 转标准像素格式或 PNG。
- 官方提供提示词调优 Skill `sd25-pe`（npx 安装）与飞书《Seedance 2.5 提示词模板》：阶段 0 阅读，用于完善检查器规则；安装运行前须征得用户同意。

## 6. 生产流水线（逐环节规格）

每个环节写明：输入、输出、实现方式、复用来源、检查点、人工确认点（自动模式下的处理）。所有语言模型步骤都是"结构化步骤"：固定提示词模板（存于 prompt_template）+ zod 输出校验 + 失败最多重试 2 次 + 记录 Token 费用。

### 6.1 导入
- 输入：TXT / DOCX / Markdown / 粘贴文本 / 已有剧本。
- 实现：编码检测（UTF-8 / GBK）；DOCX 解析优先复用服务端已有依赖 `@firecrawl/anydoc`（阶段 0 核实能力）；**章节切分用正则规则**（"第X章/回/节"等），失败时退回按字数切分，切分结果让用户可调整。
- 输出：source_document、source_chapter，原文永久保存。
- 已有剧本导入：解析为结构化剧本（6.4 的格式），跳过 6.2–6.3。

### 6.2 原著分析（逐章，长篇不整本塞进模型）
1. 文本清洗（去广告、空行、乱码），保留段落编号用于证据。
2. 逐章结构化提取：事件（Toonflow 七字段：来源章节、涉及角色、核心事件、主线关系、信息密度、预估时长、情绪）+ 角色、地点、关系、状态变化，**每条带证据（章节+段落区间）**。提示词融合 Toonflow `sourceEvents.md` 与 Jellyfish `element_extractor` 的字段定义。
3. 实体合并（移植 Jellyfish `entity_merger`）：别名归并、稳定 ID、首次出场；冲突进入候选。
4. 章节摘要 + 人物状态快照：处理下一章时只带"前文摘要 + 相关人物当前状态 + 检索到的相关事件"，控制上下文长度。
5. 建立 FTS5 索引，供后续检索。
6. 全书层面：主线、冲突、高潮、结局分析（基于各章摘要与事件，不读全文）。
- 输出：story_event、event_relation、character_relation、character_state、chapter_summary、候选。
- 人工确认点：人物合并结果与主要人物清单（自动模式：置信度 ≥ 阈值自动确认）。

### 6.3 改编规划
- 输入：全书分析结果、用户设置（总集数、每集时长、风格、节奏、对白风格、情绪强度、受众）。
- 实现：结构化步骤生成故事核、人物弧、改编原则与边界、删改记录、**分集大纲**（每集对应的事件 ID、开场钩子、核心冲突、反转、结尾悬念）。提示词吸收 Toonflow `scriptCraft.md`、`narrativeGenres.md`、`adaptationStrategy.md`、`storySkeleton.md` 的方法。
- 检查：每集事件覆盖不重叠不遗漏主线、节奏分布、悬念位置。
- 人工确认点：分集大纲（自动模式：检查通过即确认）。

### 6.4 单集剧本
- 输入：本集大纲 + 检索到的原著片段与事件 + 相关人物当前状态 + 上一集结尾。
- 输出格式（结构化 JSON，存 script_version）：场次列表 → 每场的地点、时间、出场角色、行列表（动作描写/对白/旁白/画外音/字幕卡，带说话人与情绪）。
- 时长估算：对白按可配置语速（默认 4 字/秒，阶段 3.5 实测校准）+ 动作描写估时，总时长偏差超 15% 时自动要求调整。
- 剧本检查（结构化步骤 + 规则）：符合原著主线、人物性格一致、人物关系正确、时间线合理、无前后矛盾、无重复剧情、无无意义对白、结尾有悬念、台词无生僻字。不合格只改对应场次。
- 每次修改生成新版本，支持对比与回滚。
- 人工确认点：剧本（自动模式：检查通过即确认）。

### 6.5 资产
1. 从剧本提取资产（移植 Jellyfish `element_extractor` 的角色/场景/道具/服装字段）→ 与已有实体查重（移植 `entity_existence`）→ 候选确认。
2. 新角色：生成角色设定（外貌、服装、声音），再用 **Seedream 5.0 文生图**生成：
   - 面部大头照（无表情、纯净背景、只含头部）——视频参考用；
   - 全身照（同一角色、默认服装）——视频参考用；
   - 设计参考用的多视图、表情、换装图（仅供确认设计，不默认送入 Seedance 2.0）。
   注意：大头照与全身照必须都是文生图原始产物才能被信任；两张图的面部一致性依赖提示词描述的一致，**阶段 3.5 实测**，必要时改用"先生成全身照，再从同一次生成的组图中选取"等方案（以 Seedream 5.0 文档能力为准）。
3. 场景：生成无人物的场景图；道具：生成道具图；画面文字：生成文字图。
4. 声音：为每个有台词角色选定豆包语音音色，生成 5–10 秒音色样本（固定样本文本），存 voice_profile。
5. 参考图分辨率不得超过输出分辨率（4.3）。优先直接以不超过输出分辨率的尺寸生成原图，避免缩放；缩放后的图片是否仍被人脸信任**未知，阶段 3.5 实测**，实测前不使用缩放版作为人脸参考。
- 锁定：用户确认后锁定；重要角色的锁定图未经用户确认不得替换。
- 人工确认点：主要角色形象与声音（**推荐始终人工确认**，这是整部剧一致性的根本）。

### 6.6 分镜
- 输入：已确认剧本、资产。
- 实现：结构化步骤把每场拆为镜头（字段见 shot 表），规则：
  - 不为凑数量拆开完整动作；一个镜头一个主运镜；对白镜头景别优先中近景/近景；
  - 动作拍点（Jellyfish `action_beats`）按时间顺序；
  - 写明人物位置与朝向，同场景内保持轴线（参考 Jellyfish 的构图锚点与视线建议生成逻辑）。
- 镜头时长由对白容量与动作估算。
- 人工确认点：可选（自动模式默认不停）。

### 6.7 片段划分（视频生成单位）
- 规则（参数可配置，阶段 3.5 校准）：
  - 只在同一场次内合并连续镜头；场次切换必然切分片段；
  - 片段时长默认 8–15 秒，上限为模型上限（2.5 为 30 秒，2.0 为 15 秒）；
  - 片段内出场角色数 ≤ 4（2.0）/ ≤ 5（2.5，建议值）；素材总数 2.0 不超过 5 个；
  - 片段内对白字数 ≤ 时长 × 语速；
  - 激烈动作戏单独成片段，并缩短时长。
- 衔接：同场景相邻片段可选"上一片段尾帧作为本片段参考"（使用前检查尾帧信任期）；默认硬切。
- 素材清单按角色首次出场顺序排列：每个角色 [大头照, 全身照]，然后场景图、道具图、文字图、角色音色样本（音频）。
- 输出：segment、shot 归属、素材清单。

### 6.8 提示词编译
见第 7 节。输出 prompt_version，必须通过检查器。

### 6.9 视频生成
1. 就绪检查：素材齐全、人脸信任未过期、提示词检查通过、模型参数合法（按任务类型）。
2. 幂等检查：同幂等键已有成功或在途任务则直接返回该任务。
3. 预算预留（第 9 节）。
4. 2.5：提交**样片**（480p，draft）→ 样片落盘 → 样片初检（第 6.13 节的确定性检查 + 可选人工查看）→ 通过则用样片任务 ID 生成正式视频；不通过则修改提示词或素材后重新出样片（计入重试次数）。2.0：直接生成（可先 480p 小样）。
5. 通过 Toonflow 媒体生成执行（复用其任务持久化、恢复、落盘）；成功后**立即下载**、记录哈希、提取尾帧。
6. 生成后检查（6.13）；不合格自动重做当前片段，最多 2 次，超过则转人工。
7. 结算费用（按返回用量与价格规则）。

### 6.10 配音
- 主路线：对白由 Seedance 原生生成（`generate_audio`），角色音色通过 voice_profile 的样本音频作为 `reference_audio`，提示词写"<角色>使用音频 N 的音色"。参考音频总时长受 2.5 上限（≤30 秒）约束，只放本片段出场的说话角色。
- 辅助路线：豆包语音合成独立生成旁白（VO）、画外音、补录句；按"音色 + 文本 + 参数"哈希缓存，文本改动只重做变化的句子。
- 发音：维护项目级多音字/生僻字替换表，编译提示词时替换。

### 6.11 字幕
- 文本始终以剧本原文为准。
- 主路线：对生成视频的音轨用豆包录音文件识别取时间戳，与剧本对白逐句对齐（文本对齐算法，识别文字只用来定位时间）；对不齐的句子标记待人工。
- 辅助路线：按 TTS 音频实际时长排时间轴。
- 输出 SRT 与 ASS；样式可配置（字体、字号、颜色、描边、阴影、位置）；字体文件随项目分发并注意许可证。

### 6.12 合成（FFmpeg，确定性，不调用任何生成接口）
1. 读取已采用的片段视频，按顺序排列。
2. 预处理：H.265 10bit → H.264 8bit yuv420p；统一 1080×1920、统一帧率（默认 30 fps，可配置）；音频统一采样率。
3. 衔接：硬切为默认；尾帧衔接片段做帧对齐；延长视频拼接处前段删 6 帧、后段删 1 帧（官方 2.0 建议，2.5 视实测调整）。
4. 音频：保留片段原生对白与音效；插入独立 TTS 旁白；每片段尾部音频淡出（消除截断杂音）；BGM 轨（用户素材库或后续接入的音乐生成）按场次情绪铺设并自动避让对白（侧链压缩或音量包络）；响度标准化（默认 -16 LUFS，可配置）。
5. 字幕烧录（可选）并同时导出独立 SRT/ASS。
6. 输出 MP4（H.264 + AAC），记录 render_job 与 final_video。
- 合成失败只重跑合成；修改字幕或 BGM 只重跑合成。

### 6.13 质量检查
**确定性检查（零费用，全部片段与成片必做）**
- 解码完整性（ffprobe + 全量解码）、时长与目标偏差、分辨率与编码；
- 黑屏（blackdetect）、长静音（silencedetect）、音画时长匹配；
- 抽帧文字识别，检测模型擅自生成的字幕、水印、Logo（OCR 方案阶段 0 选型，优先本地离线方案）；
- 人数检测（人脸/人体检测，本地方案）对照片段出场人数，发现分身或多人；
- 成片：字幕缺失、无声片段、音画同步（对白时间与字幕时间偏差）。

**AI 检查（可选，计费，抽帧）**
- 用视觉模型对比角色参考图与关键帧：身份一致、服装正确、场景正确、肢体畸形、眼睛发光等；
- 剧情层面：台词是否符合人设、前后矛盾（基于剧本与证据，文本模型）。
- AI 结论作为参考，与确定性检查合并给出"通过 / 自动重做 / 待人工"。

**重做策略**：每片段自动重做上限 2 次（可配置）；第二次重做前自动调整（加强对应约束句、减少素材、缩短片段）；仍不合格转人工并给出具体原因。

## 7. 提示词工程

### 7.1 编译流程

```
片段数据（镜头、对白、资产、上下文）
  → 上下文构建（移植 Jellyfish shot_video_prompt_pack 的承接、构图、视线、动作拍点逻辑，只作为输入资料）
  → 选择模板（按锁定的视频模型：2.5 模板 / 2.0 模板）
  → 语言模型按模板逐段填写（输出 zod 校验的结构化 JSON，不直接输出整段文本）
  → 代码组装成最终提示词 + 素材顺序表
  → 发音替换、敏感词处理
  → 静态检查器（7.3）
  → 保存 prompt_version
```

**原则**：模板骨架、素材指代、约束段、符号格式全部由代码生成；语言模型只填写"一句话概述、每段的动作/表情/运镜/台词情绪/音效、结尾氛围"这些创作性内容。

### 7.2 模板

**Seedance 2.5 模板（默认）**

```text
【素材】图片1是{角色A}的面部，图片2是{角色A}的全身妆造；图片3是{角色B}的面部，图片4是{角色B}的全身妆造；图片5是{场景}的场景参考；{角色A}使用音频1的音色，{角色B}使用音频2的音色。
【音频约束】只保留角色人声、环境音和动作音效；不要音乐、背景音乐、BGM、配乐、器乐、旋律、合成器音效、氛围铺底音。不要字幕。
【概述】{一句话：主体 + 地点 + 事件 + 题材风格}。
0-4秒：{景别 + 单一运镜}。{角色A}在{位置}面朝{方向}，{动作与可见表情}。{角色A}台词（{情绪}）："{原台词}"。<{音效}>
4-9秒：……
9-13秒：……
【全片】{贯穿全片的机位风格、环境、光线、氛围}；{画质与风格短语}。
【约束】人物面部与参考图保持一致；全程只有{N}名角色，禁止同款分身、双胞胎，同一画面每个角色只出现一次；人物眼睛为正常人眼；不要字幕、不要水印、不要 Logo、不要文字。只保留角色人声、环境音和动作音效，不要任何音乐。
```

**Seedance 2.0 模板**：沿用 Toonflow `videoPromptCraft.md` 的三段式（主体定义 → 镜头 1/2/3 → 风格约束），不写秒数，台词用 `{}`、音效用 `<>`，动作以缓慢连贯为主。

**图片模板**：按《Seedream 4.0-5.0 提示词指南》在阶段 0 制定（角色大头照、全身照、场景图、道具图、文字图各一套），吸收 Toonflow `imagePromptCraft.md`、`assetDesign.md`、`visualStyles.md` 与 Jellyfish `shot_frame_prompt_agents.py` 的规则。

**语言模型步骤模板**：每个结构化步骤（6.2–6.7、7.1）一套，存 prompt_template，系统预置版本只读，用户可复制修改。

### 7.3 静态检查器规则（发送前必过，零费用）

| 编号 | 规则 | 适用 |
|---|---|---|
| P01 | 提示词中的图片/视频/音频编号与实际上传顺序和数量一一对应，无缺号、无多余 | 全部 |
| P02 | 素材顺序符合角色首次出场顺序 | 全部 |
| P03 | 每个出场角色都有素材绑定句，全文称呼一致 | 全部 |
| P04 | 2.5：时间戳为连续整数秒，从 0 开始，无断档无重叠，末尾等于片段时长 | 2.5 |
| P05 | 2.0：不出现秒数时间戳 | 2.0 |
| P06 | 每个时间段/镜头最多一个主运镜词 | 全部 |
| P07 | 台词格式为 `角色台词（情绪）："内容"`，台词之后不出现对台词的复述 | 全部 |
| P08 | 台词与剧本原文逐字一致（替换表除外） | 全部 |
| P09 | 不含强烈情绪词黑名单（可配置） | 全部 |
| P10 | 约束段包含：无字幕、无水印、无 Logo、禁止分身、角色人数 | 全部 |
| P11 | 禁止 BGM 的同义词清单完整，且在开头与结尾各出现一次 | 全部 |
| P12 | 素材数量与人数在建议范围内（2.0：素材 ≤5、人物 ≤4；2.5：主体图 ≤8、主体 ≤5） | 全部 |
| P13 | 参考图分辨率 ≤ 输出分辨率；图片为标准像素格式 | 全部 |
| P14 | 人脸参考图在信任期内且为原始产物 | 全部 |
| P15 | 每段内容量与时长匹配（对白字数 ≤ 时长 × 语速） | 全部 |
| P16 | 不含内部 ID、文件名、工具说明、"避免跳轴"一类给人看的说明文字 | 全部 |
| P17 | 不含生僻字、多音字（按替换表） | 全部 |
| P18 | 提示词总长度不超过配置上限 | 全部 |

检查器输出：通过 / 不通过（规则编号 + 位置 + 修改建议）。自动模式下，不通过时先由代码自动修正可机械修正的项（P05、P10、P11、P17），其余回到语言模型重填一次，仍不通过转人工。

### 7.4 模板版本与数据驱动优化
- 模板有版本号；每次生成记录使用的模板版本。
- 统计每个模板版本：一次通过率、平均重做次数、每秒合格成片成本、各失败原因分布。
- 修改模板必须新建版本，并在基准片段集上做 A/B（样片模式，480p）后才能设为默认。

## 8. 任务、幂等与恢复

### 8.1 两层任务
- **执行层**：Toonflow 媒体任务（`utils/media/tasks.ts`），负责单次生成的提交、等待、恢复、落盘。**不修改其语义**。
- **生产层**：generation_task，负责归属、幂等、预算、重试策略、状态展示，并记录对应的 Toonflow 媒体任务 ID。

### 8.2 幂等键
`hash(项目 ID, 目标对象 ID, 任务类别, 模型, 提示词版本 ID 或输入快照哈希, 素材哈希列表, 关键参数, 重试序号)`
- 同幂等键存在 succeeded：直接返回结果，不提交。
- 同幂等键存在 reserved / submitted / running：返回该任务，不提交。
- 用户点"重做"时重试序号 +1，生成新幂等键（这是有意的付费行为，需要通过预算检查）。

### 8.3 提交顺序（防重复付费）
1. 事务内：幂等检查 → 预算预留 → 写 generation_task（reserved）。
2. 调用 Toonflow 媒体生成；供应商接单后通过 `saveTaskData` 持久化供应商任务 ID，生产层同步更新为 submitted。
3. 程序崩溃或重启：对 reserved（未拿到供应商任务 ID）的任务，**先查询 Toonflow 媒体任务记录**；能确认未提交则释放预留并标记可重提；无法确认则标记"待对账"，不自动重提，提示用户。对 submitted / running 的任务只调用 `resumeTask` 等待结果。
4. 结果落盘、哈希校验成功后才标记 succeeded 并结算。

### 8.4 错误分类
| 类别 | 例子 | 处理 |
|---|---|---|
| 可重试（不计入重做次数） | 网络超时、限流、5xx | 指数退避重试，最多 3 次 |
| 内容不合格 | 检查发现分身、字幕 | 计入重做次数，按 6.13 策略 |
| 参数错误 | 任务类型与参数不符 | 不重试，标记缺陷，修复代码 |
| 审核拦截 | 平台安全审核失败 | 不自动重试，提示用户修改内容 |
| 余额/权限 | 余额不足、模型未开通 | 暂停全部付费任务，提示用户 |

错误码映射表以火山官方错误码文档为准（阶段 0 整理）。

## 9. 成本与预算

### 9.1 账本
- 每次付费调用写 cost_ledger：预估（提交前按价格规则计算）→ 预留（占用预算）→ 结算（按返回用量 × 价格规则；无法得到用量时保留预估并标记"待对账"）→ 释放（失败且平台不扣费时）。
- 样片、正片、重做、废弃（生成了但未采用）分别统计。
- 定期调用 `getBalance` 与账本对账，差异提示用户。

### 9.2 价格规则
- 价格规则由用户录入或确认，记录计费单位（如百万 tokens）、单价、币种、来源链接、更新时间。**系统不内置任何未经核实的价格**；没有价格规则的模型禁止在自动模式下调用。
- Seedance 的 token 计算方式（与分辨率、时长、帧率的关系）阶段 0 从官方文档整理，用于预估。

### 9.3 预算
- 范围：单集、项目、每日、单模型。
- 阈值（可配置）：70% 提醒；90% 暂停启动新的付费视频任务，等待确认；100% 停止所有新付费任务。
- 判断一律在后端、在预留事务中完成：`已结算 + 在途预留 + 本次预估 ≤ 额度`。
- 预算修改写 budget_log（谁、何时、从多少改到多少、原因）。

### 9.4 成本优化手段（内置）
1. 2.5 样片先行：结构、动作、构图不对在 480p 阶段就发现。
2. 静态检查器在提交前拦截问题提示词。
3. 片段划分合理化：激烈动作戏缩短片段，降低整段报废代价。
4. 资产复用：锁定资产不重复生成；同一角色音色样本跨集复用。
5. 合成、字幕、BGM 修改不触发生成。
6. 按模板版本数据淘汰低通过率模板。

## 10. 生产调度器

- 位于生产层，单进程内运行，状态全部持久化在生产库，重启后从库中恢复。
- 工作单元：`(剧集, 环节, 对象)`；依赖关系由流水线定义（例：片段视频依赖资产锁定与提示词通过）。
- 功能：整集自动、多集批量、暂停/继续/取消（取消已提交的任务时调用 Toonflow `tasks/cancel`，并按平台规则处理费用）、单环节重跑、单片段重做、优先级、并发上限（全局与按模型，默认视频并发 2，可配置，阶段 0 查官方并发限制）、超时、限流退避。
- 停止条件：预算阈值、连续失败超过阈值（默认同一剧集 3 个片段转人工即暂停该集）、余额不足、人脸信任即将过期、需要人工确认的节点（按运行模式）。
- 运行模式：
  - **自动**：只在预算与异常时停；
  - **半自动（推荐默认）**：额外在"主要角色形象与声音确认"和"成片审核"处停；
  - **逐步**：每个环节都停（等同 Toonflow 原有体验）。
- 调度器不调用语言模型做流程决策；"导演"的规划是确定性规则，见第 11 节。

## 11. Agent 设计

### 11.1 三层职责落地

| 层 | 实现 | 说明 |
|---|---|---|
| 导演 | 调度器 + 流水线状态机（确定性代码）；需要创作判断时调用结构化步骤（如分集规划） | 不用自由 Agent 决定流程与花钱 |
| 执行 | 各结构化步骤：编剧、分集、资产提取、分镜、片段划分、提示词填写、配音、合成 | 每个步骤有固定输入输出 schema、权限（只能写自己负责的表） |
| 监督 | 质量检查模块（规则 + 可选视觉/文本模型）+ 重做策略 + 预算守卫 | 决定通过、重做、转人工，并记录原因 |

Agent 之间通过生产库记录和 zod 校验的 JSON 交互，不互相传递长篇自然语言。

### 11.2 与 Toonflow 原有 Agent 的关系
- 保留 Toonflow 的对话 Agent、技能、MCP，作为用户的创作助手。
- 新增一组 Agent 工具（`packages/tools` 下新包，或在生产包内注册到 `createAgentTools`，阶段 0 确定接入点）：查询生产状态、读取剧本/片段/资产、修改剧本某场并生成新版本、请求重做某片段（仍走预算与确认）、把片段投影到画布。
- 通过 MCP 暴露同样的工具，方便外部工具操作。
- Agent 工具对付费操作一律走生产层接口，不能绕过预算与幂等。

### 11.3 编剧知识的使用
Toonflow 的 `scriptCraft.md`、`narrativeGenres.md`、`shotCraft.md`、`assetDesign.md`、`visualStyles.md` 等不再由 Agent 整篇阅读，而是**拆解成各结构化步骤的系统提示词片段**，按题材与风格选择性注入，控制 token 消耗并保证稳定。

## 13. 画布与数据库的关系

- **生产库为真，画布为视图。** 规则必须简单，避免双向同步混乱：
  1. "投影到画布"：把某集或某片段生成到画布（文本节点放剧本与提示词，图片节点放资产，视频生成节点预置提示词、素材连线和模型配置）。投影是一次性生成，带上生产库对象 ID 与版本。
  2. 用户在画布上手动调整提示词并生成视频后，在片段上执行"采用画布结果"：系统读取该节点的输出与提示词，写回生产库为新的 prompt_version 和 media_output，并补记费用（通过 Toonflow 媒体任务记录关联）。
  3. 生产库更新后，画布上旧投影标记"已过期"，不自动覆盖用户画布。
- 画布上手动发起的生成也必须经过预算守卫：在执行层的媒体生成入口加一个可选钩子（仅当工作区属于生产项目时生效），**这是对 Toonflow 原文件的少数必要修改之一**，改动保持最小并写清楚。

## 14. 安全与数据管理

- **监听地址**：修改 `apps/server/src/index.ts`，默认监听 `127.0.0.1`；需要局域网访问（Toonflow 的移动端互联功能）时由用户在设置中显式开启，并提示风险。阶段 0 确认桌面端（`apps/desktop`）与移动互联（`utils/mobileLink`）对监听地址的依赖，避免改坏原功能。
- **密钥**：火山 API Key 只存在服务端（沿用 Toonflow 供应商配置的存储方式，`settings.json` 权限 0o600）；生产库、任务快照、日志、错误信息一律不含密钥（沿用 `ProviderTools.errorMessage` 脱敏）。
- **路径**：所有文件操作限制在工作区与数据目录内（沿用 Toonflow 的工作区路径校验）。
- **备份与恢复**：
  - 项目备份：导出整个项目工作区（含 `.production/production.db` 与 `assets/`）为压缩包，附全局库中该项目的账本导出；
  - 全局备份：`data/` 下设置、全局库、供应商配置（密钥可选择不导出）；
  - 恢复：导入压缩包，校验哈希与数据库版本，必要时运行迁移。
  - 原始参考图随备份保留；恢复后信任是否仍有效以平台规则为准（同账号、30 天）。
- **删除**：删除项目、资产、成片需二次确认；遵守 Toonflow `AGENTS.md` 的删除保护规定。
- **外发**：除火山方舟外，不把素材、文本或密钥发送到任何未经用户授权的服务。

### 阶段 1：运行基线

### 阶段 2：生产底座（零费用）

### 阶段 3：火山供应商与一集最小闭环
任务：实现 `volcengine.ts`（Seedream 5.0 文生图、Seedance 2.5/2.0 含样片与尾帧、豆包语音合成、录音文件识别——识别若不适合放在媒体供应商接口中，则放生产层适配器）；提示词编译器与检查器（2.5 与 2.0 两套）；合成引擎（转码、拼接、淡出、字幕烧录、BGM 轨、导出）；确定性质量检查。用一份手写的结构化剧本（不经小说导入）手动走通：资产 → 片段 → 提示词 → 视频 → 字幕 → 合成。
验收：先全 Mock 跑通得到 MP4；再经用户同意，用真实 API 跑 2–3 个片段（480p 样片为主），得到可播放的 MP4，所有费用在账本中且与平台对账一致。

### 阶段 3.5：提示词与参数基准测试（关键闸门）
任务：固定 1 场戏、2 个角色、3 个片段，全部用 2.5 样片模式（480p）：
- A 组：Toonflow 原 2.0 式模板 + 三视图参考；
- B 组：第 7 节 2.5 模板 + 大头照/全身照参考；
- 每组每片段 3 次；同时实测：动漫/3D 风格是否触发人脸审核、图生图与缩放后的图片是否仍被信任、大头照与全身照的面部一致性、语速参数、片段时长 8 / 12 / 15 秒的通过率差异。
验收：对照报告（各组一次通过率、各失败原因占比、实际花费）。**B 组明显优于 A 组才进入阶段 4**；否则调整模板继续测试。花费上限事先由用户确认。

### 阶段 4：资产系统
任务：资产提取、查重、候选确认；角色设定与 Seedream 生成；锁定；音色样本；人脸信任到期管理；资产库界面。
验收：同一角色跨片段复用同一组参考图；锁定资产不会被覆盖；到期预警可触发（用模拟时间测试）。

### 阶段 5：分镜与片段
任务：分镜结构化步骤；片段划分规则；衔接方式；分镜工作台界面；画布投影与"采用画布结果"。
验收：8–12 个镜头的剧集能自动生成合规片段；用户在画布上修改并采用后，生产库正确更新。

### 阶段 6：配音与字幕
任务：音色样本参考接入；独立 TTS 与缓存；录音文件识别对齐；SRT/ASS；发音替换表。
验收：修改一句旁白只重做一句；字幕与对白时间偏差在可接受范围（阈值阶段 3.5 定）。

### 阶段 7：完整合成与质量检查
任务：BGM 与避让、响度标准化、衔接处理、导出历史、重新合成；OCR 与人数检测、AI 抽帧检查、重做策略。
验收：合成失败重跑不产生费用；能检出黑屏、静音、多余字幕、分身。

### 阶段 8：小说导入与编剧
任务：多格式导入与章节切分；逐章分析、实体合并、证据、FTS5；改编规划、分集大纲、单集剧本与检查、版本管理；剧本工作台界面。
验收：一部中篇小说生成分集大纲与第 1 集剧本，事件可追溯到原文段落。

### 阶段 9：自动调度与批量
任务：三种运行模式；整集与多集批量；暂停/继续/取消；并发与限流；停止条件；生产控制台界面。
验收：中途关闭程序后重启能继续且不重复付费；预算阈值正确停止。

### 阶段 10：界面完善与 Agent 工具
任务：项目首页、成本中心、成片管理补齐；生产相关 Agent 工具与 MCP 工具。
验收：所有按钮真实可用；Agent 能查询状态并在预算约束下请求重做。

### 阶段 11：打包与完整验收
任务：Windows 安装包；文档；第 19 节全部场景。
验收：通过第 19 节。

## 19. 最终验收

**测试素材**：一个故事梗概或短篇小说，至少 2 个主要角色、3 个场景；生成 1 集、8–12 个镜头、9:16、1080×1920，包含参考图、视频、原生对白、旁白、字幕、BGM、自动合成，导出 MP4。

**必须通过的场景**（2–15 用 Mock 与故障注入，场景 1 用真实 API 且事先经用户同意预算）：
1. 正常生产
2. 图片生成失败
3. 视频生成失败
4. API 超时
5. 重复点击提交（只产生一次付费请求）
6. 生产中途关闭程序
7. 重启后恢复（在途任务对账，不重复提交）
8. 单片段重做
9. 预算达到 90%
10. 预算达到 100%
11. 合成失败后重新合成
12. 成片重新导出（改字幕或 BGM）
13. 角色参考图人脸信任即将到期的预警与处理
14. 生成结果在 24 小时内自动下载的保护（模拟断网后恢复补下载）
15. 提示词检查器拦截不合规提示词，且不产生费用

**核心要求**：已成功的产物不会因为任何失败而重新付费生成。

**最终目标**：A 导入小说　B 分析事件与人物关系　C 生成分集剧本　D 建立人物与场景资产　E 自动拆镜与划分片段　F 生成参考图　G 生成片段视频　H 角色对白与旁白　I 生成字幕　J 自动合成成片　K 检查成片质量　L 查看每集真实成本　M 限制 API 支出　N 暂停、恢复、重做　O 批量多集　P Windows 本地稳定运行　Q 备份与恢复全部项目资料
